Offline Brain Agent 1.0.3 — Round 4 Report

Result at a glance

Debug, release and Android UI-test APKs all built, and the debug/release APK signatures verify. Root causes for the reported failures

A — OCR: The supplied failure text identifies a null access inside obfuscated ML Kit code, but it is only one exception line—not a full Java stack trace—and no mapping file for the failing 1.0.2 APK was supplied. I could not faithfully deobfuscate that old line. The new 1.0.3 release mapping is supplied for traces from that exact release; it contains no yd5 or zc5 entries, so it cannot safely map those old names. The R8 rules and background/lifecycle changes are mitigations, not proof of the original cause. If the 1.0.3 test fails, capture the full trace and use the 1.0.3 mapping only with that build.
B — Notifications: Android had granted access, but MIUI had disconnected/killed the listener. The app now requests Android rebind and offers component repair, visible keep-alive and a periodic check; MIUI battery/autostart restrictions can still block it. Follow the phone checklist to see whether this firmware accepts the repair.
C — Microphone: The old UX relied on an external recognition intent/dialog, which could return the repeated prompt without giving the app a useful live transcript or actionable status. Round 4 listens inside the app and maps recognizer errors to hints. The specific on-device error and whether an offline language pack fixes it were not available to reproduce here.
D — Clock: setAlarmClock() schedules an alarm for the app through Android; it does not guarantee that a vendor Clock app imports it into its own alarm list. The new optional Android Clock intent asks the system Clock app to set a one-time alarm. Xiaomi Clock's response must be verified on the Redmi.

How to use phrases, macros and the floating button

Teach a phrase: Go to Tools → Phrases and macros → Teach a phrase. Step 1 is the words to match, Step 2 chooses weather, news, alarm, app, macro or custom reply, and Step 3 tests the fixed-word match before Save. The one-tap starters include “good morning” (weather plus headlines), “weather please”, “latest headlines”, “my notifications” and “remind me”. The Test step only checks the local word match; it does not actually set an alarm or open an app.

Record a macro: Open Tools → Phrases and macros, name the recording and tap Record macro. With Android Accessibility enabled, switching apps, tapping labeled controls and typing in accessible non-password fields can become live steps such as “Open WhatsApp”, “Tap Search”, “Type Mom”. These steps remain in memory until Stop and save; Stop and discard clears them. Password-marked fields are skipped, but other private text or codes might still be captured, so use a harmless test screen and never record secrets. Review the steps before playing; you can stop playback from Chat. Without Accessibility, recording only captures Chat requests.

Set up the floating button: Open Settings → Tools → Set up floating button. Step 1 opens Android's overlay-permission page; after allowing it, return and tap the permission test. Step 2 starts the button, and Step 3 explains how to use it as a shortcut to Chat and stop it. The button does not read or tap another app by itself; stop it from the setup page or its notification.

Diagnostics, performance and what remains UNTESTED

The final command was ./gradlew testDebugUnitTest assembleDebug assembleRelease assembleAndroidTest --stacktrace; it completed successfully. JUnit XML reports 28 tests, 0 failures, 0 errors and 0 skipped. Both app variants compiled, the test APK assembled, and apksigner verify passed. The instrumented tests now cover the Chat input/nav check and the repeating-alarm swipe/Undo flow, but neither test was executed. A successful build is not a Redmi runtime pass.

The hand-authored baseline-prof.txt (app/src/main/baseline-prof.txt) lists three hot methods for Activity start, ViewModel creation and encrypted database acquisition. It is not a device-generated profile, and no cold-start, memory, frame-drop, power or PDF/OCR timing was measured. The source already packages the hand-authored profile; no app-specific speed improvement is claimed. To create measured numbers later, Android's Macrobenchmark guide (https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview) recommends adding a separate Benchmark module in Android Studio, making the app profileable and release-like, then measuring cold startup and real navigation/scroll flows on the Redmi. Run that module's connected benchmark test on the device and save its timing JSON/trace. To generate a real Baseline Profile, follow Google's profile-generation guide (https://developer.android.com/topic/performance/baselineprofiles/create-baselineprofile); use the generated profile only after a successful device run.

Android's AccessibilityService reference (https://developer.android.com/reference/android/accessibilityservice/AccessibilityService) says services should assist users with disabilities and are enabled by the user in Android Settings. The project uses explicit, local, user-started Accessibility capture and is delivered as a sideload-test APK; any Google Play distribution would require a separate review of current Accessibility-service eligibility and disclosure rules.

Exact Redmi M2006C3MII phone test checklist

The user previously observed these passes on the Redmi M2006C3MII/Android 11/MIUI: alarm, Stop/Snooze, en-IN TTS, Accessibility binding, screenshot, network and WhatsApp notification capture. Those results predate the 1.0.3 changes and are not Round 4 regression passes.

1. Protect existing data and install: First create and verify an encrypted backup. Install the release APK over 1.0.2 only if its signing certificate matches; do not uninstall to work around a signature mismatch before checking the backup. The debug build uses a separate package name and can be installed alongside release.
2. Layout and navigation: On the Redmi in portrait, check normal and large display/font sizes, both 3-button and gesture navigation, and 720×1560 at 320 dpi if available. Open Chat, show the keyboard, type and send a harmless message; confirm the composer, five-tab bar, phone status bar and system navigation remain usable. Run the instrumented UI test if Android Studio/ADB is available.
3. OCR debug versus release: Run Settings → Diagnostics → Run all diagnostics first in debug and then release; compare the bundled OCR sample result. If release still fails, copy the full report and exact stack trace, note the APK version, and use only the 1.0.3 release mapping. Do not assume the old yd5 line is decoded by this map.
4. Speech: Test microphone input with en-IN, partial text and one short sentence. Turn network off to check whether the installed recognizer can work offline; if not, install its offline English/India voice pack and retry. Record the exact error and whether en-US fallback occurs.
5. Notification repair and privacy: Enable Notification Access, then separately turn live capture on. Send harmless test notifications from WhatsApp, Messages/SMS, email, music and weather apps; check category totals, duplicate handling, WhatsApp chat grouping, last-saved time, search, Mark all read and Clear category. Confirm caller and SMS bodies stay hidden by default. If status becomes disconnected, tap Fix listener connection; if needed, allow Background autostart, choose No restrictions for battery, lock the app in Recents where MIUI offers it, then try the optional visible keep-alive.
6. Alarm lifecycle and Clock: Add a test one-time alarm and confirm it disappears after Stop. Snooze it and confirm the replacement disappears after its final Stop. Add a repeating alarm, swipe it left and tap Undo; repeat and allow deletion to finish. Edit, disable/enable and delete another repeating alarm. Separately test the Clock mirror with the switch off and on, and check whether both the app and Clock can ring.
7. Phrases and macros: Add “weather please”, test the fixed-word match, save, trigger it and delete it. Then enable the app's Accessibility service, record the harmless “Open WhatsApp → Tap Search → Type Mom” example in a test chat, verify the live list, Stop and save, review and play it, then stop playback. Test Stop and discard too. Never record passwords, OTPs, private messages or payment screens.
8. Floating button and MIUI: Use the three-step setup, grant overlay permission, tap the permission test, start the button, open Chat from it and stop from both the app and its ongoing notification. Apply Xiaomi's Autostart guidance (https://www.mi.com/global/support/faq/details/KA-507611/) if MIUI stops it.
9. Backup, lock and wipe: Run the backup/wrong-passphrase diagnostics with disposable data, export and restore a test backup, and check PIN/biometric lock behavior without using a personal PIN in diagnostic text. Confirm Wipe asks you to type WIPE; only test it after verifying a separate backup.
10. Final report: Open Diagnostics, run the checks again, review each UNTESTED result, and tap Copy full diagnostic report. The copied block includes app/device/build version and every result; share it only if you want to provide the phone-test outcome.
