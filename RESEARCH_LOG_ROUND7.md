# Round 7 research log — Offline Brain Agent

**Scope and evidence rule.** Research conducted 2026-11-12 before implementation for the user-specified workstreams. Project constraints: Kotlin/Compose, min/target SDK 30, compile SDK 36, armeabi-v7a only, no LLM/cloud AI. The Redmi M2006C3MII / MIUI V12.5.6.0 / Android 11 / 3.7 GB RAM and 2% battery details are owner observations, not independently verified measurements. Each workstream was researched separately using current official Android/Kotlin/AndroidX and primary Xiaomi sources where available. All 14 research units returned; no workflow unit failed. Across these sources, **no exact primary-source documentation was found for a bug on this exact model/build**. Lack of a public report is not proof that no device-specific defect exists. Use direct handset tests to establish behavior.

## A. Microphone, Android speech service and Vosk

**Research decisions.** Keep one serialized, main-thread `SpeechRecognizer`; set callbacks before starting; destroy on session completion/disposal. On ERROR_RECOGNIZER_BUSY (8) or ERROR_CLIENT (5), cancel/destroy and recreate once, then fail clearly rather than loop. Android provider recognition may send audio remotely and must not be labeled offline. Query providers using the Android 11 manifest `<queries>` for `android.speech.RecognitionService`; distinguish Auto, Android and explicitly selected Offline (Vosk). API-31 on-device recognition APIs are unavailable on Android 11. Check `RECORD_AUDIO`; one-time grants and repeated denial need Settings recovery. Audio focus governs playback, not exclusive mic ownership; request/abandon it only if the app itself plays a prompt. Keep Vosk opt-in/on-demand, validate model/ABI, download with truthful progress and integrity/free-space checks, load off main thread, release after a bounded listening task, and catch OOM at the resource boundary. Vosk small models are listed at roughly 36–50 MB on disk and ~300 MB runtime memory; target-device memory has not been measured. Separate an AudioRecord signal test from recognizer/provider tests.

**Sources.** [SpeechRecognizer API](https://developer.android.com/reference/android/speech/SpeechRecognizer) (live reference; on-device-only API is API 31); [Android 11 package visibility](https://developer.android.com/about/versions/11/behavior-changes-11); [Audio focus](https://developer.android.com/media/optimize/audio-focus); [AudioRecord API](https://developer.android.com/reference/android/media/AudioRecord); [Android 11 permissions](https://developer.android.com/about/versions/11/privacy/permissions) (last updated 2026-10-28); [RECORD_AUDIO](https://developer.android.com/reference/android/Manifest.permission#RECORD_AUDIO); [Vosk Android](https://alphacephei.com/vosk/android); [Vosk models](https://alphacephei.com/vosk/models); [Vosk Android demo](https://github.com/alphacep/vosk-android-demo); [Xiaomi 13T voice-input FAQ](https://www.mi.com/global/support/faq/details/KA-548608/) (not the user's model/build).

**Key unknown/test.** Installed provider identities, languages/offline behavior, model ABI and peak native memory are unknown. No exact MIUI mic issue found. On API 30 exercise absent/multiple/disabled providers, permission grant/revocation, errors 8/5, airplane mode, no speech, repeated starts and process/lifecycle cleanup; measure Vosk memory/latency on target.

## B. Floating overlay / mini assistant

**Research decisions.** Use `SYSTEM_ALERT_WINDOW` plus `TYPE_APPLICATION_OVERLAY`, runtime `Settings.canDrawOverlays()` gating and recheck after Settings. On API 30 do not assume package URI targeting for `ACTION_MANAGE_OVERLAY_PERMISSION`; provide standard App Info/manual fallback. Own one root view per service; explicitly track attached state and guard add/update/remove; catch `BadTokenException` with diagnostics. Start a user-initiated foreground service while the app is foreground and promote promptly with a visible notification. Keep bubble compact, touch/focus behavior deliberate, persist/clamp position across display changes. Xiaomi `APP_PERM_EDITOR` is vendor-specific best effort only; it must not be the sole route. MIUI popup/background/lockscreen controls can be separate from Android overlay access, but exact labels and behavior must be observed on-device. No keyguard overlay capability is claimed.

## C. Notification cards/actions and privacy

**Research decisions.** Use accessible Compose semantics for category headings, cards and independently named actions. `Open` only when a real content PendingIntent exists; `Reply` only when a real `RemoteInput` and action PendingIntent exist; `Mark read` only when the actual supported action exists. Invoke the original PendingIntent and report failures; do not infer an operation from its label. Use local Android `TextToSpeech` and declare the TTS service query for target API 30. Calls/SMS show sender only until explicit “Show text”; hidden text must not leak through TalkBack, clipboard or TTS. Use narrow package queries for labels/icons and safe fallback when metadata is filtered/missing. No exact MIUI card/action defect found.

## D. Notification category query engine

**Research decisions.** Keep a local deterministic typed parser: explicit verbs/category synonyms, edit distance ≤2 only over the short command vocabulary, clarify ambiguous matches. Define unread as an app-level per-category last-seen marker and advance only when the user views that category. Use `StatusBarNotification.getPostTime()` with local-day half-open boundaries for “today”; match app/contact only from available package/person metadata. Category questions are final local intents and never fall through to Wikipedia/network. Do not promise historical notifications unavailable after listener access/disconnection.

**Sources.** [NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService); [StatusBarNotification](https://developer.android.com/reference/android/service/notification/StatusBarNotification); [Notification](https://developer.android.com/reference/android/app/Notification); [LocalDate](https://developer.android.com/reference/java/time/LocalDate) (API 26+, available on API 30); [Room local database](https://developer.android.com/training/data-storage/room) (current page references Room 3.0.3; do not upgrade without build compatibility checks); [Kotlin stdlib](https://kotlinlang.org/api/core/kotlin-stdlib/); [Xiaomi support](https://www.mi.com/global/support).

## F2. Media volume

**Research decisions.** Use `AudioManager.STREAM_MUSIC`; one-step up is `ADJUST_RAISE`; explicit percent maps to nearest discrete index via documented half-up integer rounding, clamped 0–max. Read back after void setter and report stream index/rounded percentage—not acoustic loudness. Handle fixed-volume no-op. Mute is explicit `ADJUST_MUTE`, separate from setting volume 0; do not modify ringer/DND. Define the ambiguous “rise volume 30” grammar before implementation; do not guess whether it means percent or steps.

**Sources.** [AudioManager](https://developer.android.com/reference/android/media/AudioManager); [Android 11 framework AudioManager source](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android11-release/media/java/android/media/AudioManager.java); [NotificationManager/DND](https://developer.android.com/reference/android/app/NotificationManager); [MODIFY_AUDIO_SETTINGS](https://developer.android.com/reference/android/Manifest.permission#MODIFY_AUDIO_SETTINGS); Xiaomi [no-sound FAQ](https://www.mi.com/global/support/faq/details/KA-491590/) is generic; [Kotlin numbers](https://kotlinlang.org/docs/numbers.html); [instrumented tests](https://developer.android.com/training/testing/instrumented-tests).

## G1. Log rotation, aggregation and package labels

## G4. Persistent release key / migration

**Research decisions.** Create one long-lived release keystore outside repo; retain protected backups, alias, password and certificate fingerprint. Initialize Vosk, PDFBox and optional ML Kit only when relevant feature opens; close native/file resources and trim reconstructible caches on UI-hidden/background. ## Cross-workstream constraints

Android documentation specifies API behavior; it cannot establish that MIUI V12.5.6.0 delivers a particular callback or exposes a particular settings screen. Do not claim an exact-device cause from a generic support FAQ, third-party ROM index, or owner report. Keep phone findings separately labeled as tests/observations. Use no broad package enumeration, do not leak notifications/passphrases in logs, do not auto-place calls, and do not silently enable a feature after the user turns it off. Project dependency/toolchain compatibility must be checked before changing any SDK/library version. Continue to verify APK `lib/` entries as armeabi-v7a only.
